# תרגיל 3 - מעקב הוצאות

בתרגיל הזה בונים אפליקציית הוצאות: מוסיפים הוצאה עם תיאור, סכום וקטגוריה, והטבלה והסכום הכולל מתעדכנים. הנתונים נשמרים במערך ב-JavaScript, והטבלה נבנית מחדש מהמערך בכל שינוי.

**מה בונים:** טבלת הוצאות עם בדיקת קלט, סינון לפי קטגוריה, מחיקה, סכום כולל ומיון.
**זמן משוער:** 50 דקות.

## איך זה צריך להיראות

🎬 **[צפו בסרטון הדגמה של האתר המוכן](https://cdn.jsdelivr.net/gh/Lior3796/dom-03-expense-tracker@main/demo.mp4)** - כך האתר צריך להתנהג כשמסיימים את כל השלבים.

## איך מתחילים

1. לוחצים למעלה על **Use this template** ← **Create a new repository**, ויוצרים ריפו משלכן.
2. עושים `git clone` לריפו החדש ופותחים אותו ב-VS Code.
3. בטרמינל מריצים פעם אחת: `npm install` (צריך Node בגרסה 20 ומעלה. בודקים עם `node -v`).
4. כותבים את כל הקוד בקובץ `script.js`. את `index.html` ו-`style.css` לא צריך לשנות.
5. כדי לראות את הדף פותחים את `index.html` עם Live Server.

## הרעיון המרכזי

שומרים את ההוצאות במערך של אובייקטים, ופונקציה אחת בשם `render` מציירת את הטבלה מהמערך:

```js
// one expense in the array
{ id: 1, desc: "Pizza", amount: 42.5, category: "food" }
```

כל פעם שמשהו משתנה (הוספה, מחיקה, סינון, מיון) משנים את המערך או את הסינון וקוראים ל-`render`. אין צורך לערוך שורות בטבלה ידנית.

## שלבים

### שלב 1: הוספת הוצאה
שליחת הטופס מוסיפה אובייקט למערך עם `id` ייחודי (מספר שעולה בכל הוספה), ומעדכנת את הטבלה. הדף לא נטען מחדש. אחרי ההוספה השדות `desc` ו-`amount` מתרוקנים וה-focus חוזר ל-`desc`.

בדיקות קלט (באלמנט `form-error` מוצגת ההודעה ומסירים ממנו את `hidden`, ובהוספה מוצלחת מחזירים `hidden`):
- תיאור ריק (גם רווחים בלבד): `Please add a description`
- סכום שאינו גדול מ-0 (ריק, 0 או שלילי): `The amount must be larger than 0`

### שלב 2: הציור של הטבלה
הפונקציה `render` מרוקנת את `rows` ובונה בשבילה שורה לכל הוצאה מוצגת, עם `createElement` ו-`appendChild`. כל שורה (`tr`) מכילה ארבעה תאים (`td`): תיאור, קטגוריה בתוך `span` עם המחלקה `badge`, סכום עם שתי ספרות אחרי הנקודה (`toFixed(2)`), וכפתור מחיקה עם המחלקה `delete` ו-`data-id` עם ה-id של ההוצאה. כשאין הוצאות להצגה מוצג האלמנט `no-rows`, ואחרת הוא מוסתר.

### שלב 3: מחיקה
מאזין אחד על `rows` מטפל בכל כפתורי המחיקה (event delegation). הוצאה נמחקת מהמערך לפי ה-id שנקרא מ-`event.target.dataset.id`, והטבלה מצוירת מחדש.

רמז: `filter` מחזירה מערך חדש בלי הפריט שרוצים להסיר. ה-`dataset` מחזיר מחרוזת, ולכן צריך להמיר אותה למספר.

### שלב 4: סכום כולל
האלמנט `total` מציג את הסכום של ההוצאות המוצגות כרגע בטבלה, עם שתי ספרות אחרי הנקודה.

### שלב 5: סינון לפי קטגוריה
בחירה ב-select עם המזהה `filter` מציגה רק הוצאות מהקטגוריה הנבחרת (או את כולן עבור All categories). הסכום הכולל מתעדכן בהתאם.

רמז: האירוע המתאים הוא `change`. `filter` על המערך מחזיר רק את ההוצאות שמתאימות.

### שלב 6: מיון
הכפתור `sort-btn` מחליף בין מצב מיון לבין סדר ההוספה. כשהמיון פעיל ההוצאות מוצגות מהסכום הגבוה לנמוך והטקסט של הכפתור הוא `Sort by amount: on`, וכשהוא כבוי `Sort by amount: off`. הסדר של המערך המקורי לא משתנה.

רמז: `toSorted` מחזירה עותק ממוין ולא משנה את המערך המקורי. הפונקציה שמועברת אליה מקבלת שני איברים `a` ו-`b`: מחזירה מספר חיובי אם `b` צריך לבוא לפני `a`, כלומר `b.amount - a.amount` ממיין מהגבוה לנמוך.

### שלב 7: הדגשה
הוצאה של יותר מ-100 מקבלת לשורה (`tr`) את המחלקה `big`.

## בדיקה עצמית
- הוספה של סכום 0 או של תיאור ריק לא מוסיפה שורה ומציגה הודעה.
- הוצאות של 42.5 ו-12 נותנות סכום כולל 54.50.
- אחרי מחיקה והוספה כל שורה מוחקת את ההוצאה הנכונה (בדקו עם שתי הוצאות באותו תיאור).
- מיון ואז הוספה של הוצאה חדשה מציג אותה במקום הנכון בסדר הממוין.
